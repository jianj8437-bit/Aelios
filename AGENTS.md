# AGENTS.md

Aelios is a long-term memory gateway that runs as a Cloudflare Worker (`companion-memory-proxy`), with D1, Vectorize, a Queue and Workers AI.

## If the user wants Aelios set up

Follow [docs/setup-with-ai.md](docs/setup-with-ai.md) step by step. It starts from a fresh Cloudflare account (fork and deploy) and covers turning Aelios into an API for the user's chat app (the provider key stored in Cloudflare AI Gateway by the user, the Cloudflare token generated by you, the first assistant configured), handing over the base URL, API key and model name, connecting the MCP connector, and importing old memories and chat logs. Users who already have Aelios skip the deploy step.

## Rules that apply to every task in this repo

- Deploy only with `npm run deploy`. A bare `wrangler deploy` does not create the database or the index.
- This is a Wrangler project. Do not run `cf dev`, `cf build`, `cf deploy` or `cf migrate` here. Use `cf` only for account resources such as AI Gateway, API tokens and Worker secrets, and for read-only commands such as `cf d1 list`.
- `npm run deploy` writes the D1 database ID and the account ID into `wrangler.toml` for that one deploy. Never commit those changes: `git checkout -- wrangler.toml` afterwards.
- Never write secrets into any tracked file, and never ask the user to paste a Cloudflare API token, GitHub token or model provider key into the chat. The user stores provider keys in Cloudflare themselves. A token you generate goes straight into a Worker secret through a pipe; never print it or write it to a file. See [SECRETS.md](SECRETS.md).
- Never delete or replace a D1 database, Vectorize index, queue, Worker, AI Gateway, stored provider key, Worker secret or configured assistant without the user's explicit go-ahead. The memories live there.

## Working on the code

- Node.js 22+. Install with `npm ci`.
- Before a PR: `npm run verify` (typecheck, tests and verify scripts) and `npm run lint`. Lint must have zero errors; the existing `noNonNullAssertion` warnings are allowed. Do not bulk-fix them with Biome's autofix, which turns `x!.y` into `x?.y`.
- Database changes are new numbered files in `migrations/`; never edit an applied migration.
- User-facing docs come in pairs: keep `README.md` and `README.zh-CN.md` in step.
